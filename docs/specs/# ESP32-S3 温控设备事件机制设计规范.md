# ESP32-S3 温控设备事件机制设计规范

**版本：V1.1**  
**平台：ESP32-S3 / ESP-IDF 6.x / FreeRTOS**

## 1. 设计目标

采用 ESP-IDF 原生 `esp_event`，以状态变化驱动模块协作，实现简单、可靠、易扩展的事件机制。

核心原则：

1. **先获取 IP，再连接 MQTT。**
2. **模块职责清晰**：Wi-Fi、MQTT、温控分别管理自身状态。
3. **安全优先**：网络异常不影响本地温控安全。
4. **事件处理轻量化**：耗时操作交给对应任务。
5. **避免重复操作**：重复事件不能导致重复连接或重复创建任务。
6. **状态可恢复**：事件丢失或处理失败时，可通过检查实际状态恢复一致性。

## 2. 模块划分

| 模块 | 职责 |
|---|---|
| `app_main` | 初始化系统和各业务模块 |
| `event_manager` | 定义应用事件、统一发布、记录事件历史 |
| `wifi_manager` | Wi-Fi 连接、IP 获取、断线及重连 |
| `mqtt_manager` | MQTT 连接、订阅、消息处理及重连 |
| `device_manager` | 判断设备就绪状态 |
| `temperature_control` | 温控逻辑、继电器控制及安全保护 |
| `led_status` | 根据系统状态显示指示灯 |

应用层使用一个自定义事件循环 `APP_EVENT`。Wi-Fi 和 MQTT 的 ESP-IDF 原生事件由对应管理模块接收，再转换为应用层事件。

## 3. 事件定义

第一版只定义以下必要事件：

| 事件 | 含义 | 处理动作 |
|---|---|---|
| `DEVICE_STARTING` | 系统启动 | 更新启动状态 |
| `WIFI_CONNECTED` | 已关联 Wi-Fi | 等待 IP 获取 |
| `WIFI_GOT_IP` | 已获取 IP | 允许启动 MQTT 连接 |
| `WIFI_DISCONNECTED` | Wi-Fi 断开 | 清除网络就绪状态，暂停 MQTT 重连 |
| `MQTT_CONNECTED` | MQTT 已连接 | 更新在线状态、订阅主题 |
| `MQTT_DISCONNECTED` | MQTT 已断开 | 更新离线状态，评估重连条件 |
| `MQTT_MESSAGE` | 收到 MQTT 消息 | 校验并分发消息 |
| `DEVICE_READY` | 本地设备就绪 | 更新设备状态 |
| `SYSTEM_ERROR` | 发生系统故障 | 记录错误并通知相关模块 |

不必为每一种内部状态都定义全局事件。连接中、重连中等状态由对应管理模块维护即可。

## 4. 优先级与安全原则

系统处理优先级：

1. **P0：安全保护及紧急输出控制**
2. **P1：基础初始化与关键模块就绪**
3. **P2：Wi-Fi 连接及 IP 获取**
4. **P3：MQTT 连接与通信**
5. **P4：设备业务及远程命令**
6. **P5：日志、统计等非关键操作**

优先级用于约束模块之间的依赖，不代表 `esp_event` 自动按照该顺序抢占执行。

**安全要求：**

- 温控安全动作不得等待事件处理。
- MQTT 断线不得导致本地温控停止。
- 传感器故障、超温和继电器保护由本地安全逻辑直接处理。
- 远程命令不得绕过本地安全限制。

## 5. 核心连接流程

```text
系统启动
   |
   v
初始化事件循环、传感器、温控及安全模块
   |
   v
启动 Wi-Fi 连接
   |
   v
Wi-Fi 获取 IP（WIFI_GOT_IP）
   |
   v
检查 MQTT 连接条件
   |
   v
启动或恢复 MQTT 连接
   |
   v
MQTT_CONNECTED
   |
   v
云端通信就绪
```

Wi-Fi 连接失败时，由 `wifi_manager` 负责重试。整个网络连接过程不得阻塞本地温控。

### MQTT 启动的必要条件

必须同时满足：

- MQTT 客户端已初始化。
- Wi-Fi 已获取有效 IP。
- 当前没有禁止通信的条件。
- MQTT 未连接，且没有正在执行的连接操作。

**必须区分 `WIFI_CONNECTED` 和 `WIFI_GOT_IP`。只有后者才能作为 MQTT 连接的启动门槛。**

## 6. 事件处理规则

### 6.1 Wi-Fi 事件

**`WIFI_CONNECTED`**

更新链路状态，等待 IP 获取，不启动 MQTT。

**`WIFI_GOT_IP`**

更新网络就绪状态，通知 `mqtt_manager` 检查连接条件。若 MQTT 已连接或正在连接，不重复启动。

**`WIFI_DISCONNECTED`**

立即清除网络就绪状态，标记云端通信不可用，并暂停应用层主动发起的 MQTT 重连。由 Wi-Fi 管理模块恢复网络。

### 6.2 MQTT 事件

**`MQTT_CONNECTED`**

更新在线状态，完成必要的主题订阅和上线状态发布。

**`MQTT_DISCONNECTED`**

更新离线状态：

- Wi-Fi 仍有 IP：允许按 MQTT 重连策略恢复连接。
- Wi-Fi 已断开：等待下一次 `WIFI_GOT_IP`。

**`MQTT_MESSAGE`**

校验主题、消息格式、参数范围及命令权限。耗时处理应交给工作任务；非法命令必须拒绝。

### 6.3 设备及故障事件

**`DEVICE_READY`**

表示本地传感器、温控及安全模块已满足运行条件。对于支持独立运行的设备，MQTT 在线不应成为本地温控就绪的必要条件。

**`SYSTEM_ERROR`**

记录错误来源和错误码，并通知相关模块。必须立即执行的安全动作，应先由安全逻辑执行，再发布故障事件。

## 7. 断线与重连策略

### Wi-Fi

由 `wifi_manager` 独立管理。建议初始重试间隔为：

`1 → 2 → 4 → 8 → 16 → 30 秒`

达到上限后保持 30 秒间隔，可按需加入随机抖动。

### MQTT

由 `mqtt_manager` 或 ESP-MQTT 客户端统一管理。

- 无 IP：不主动发起 MQTT 连接。
- 有 IP 且 MQTT 未连接：允许恢复连接。
- MQTT 已连接或正在连接：不重复启动。
- Wi-Fi 恢复并重新获取 IP：重新检查 MQTT 状态。
- 连接失败：按退避策略等待，不得忙循环。

**只能有一套明确的 MQTT 自动重连责任方。** 如果使用 ESP-MQTT 内置自动重连，应结合实际客户端行为配置，避免应用层再次启动独立的无限重连循环。

## 8. 实现约束

1. 事件处理函数只做状态更新、轻量记录及非阻塞通知。
2. 网络等待、复杂 JSON 解析等耗时工作交给对应任务。
3. 共享状态应采用适当的同步方式，避免多个任务无保护地读写。
4. 异步事件不得携带已经失效的栈变量指针。
5. 检查 `esp_event_post()` 的返回值，处理事件投递失败。
6. 建议使用固定容量的 32 条事件环形记录，仅保存时间、事件 ID、来源和错误码。
7. 事件历史不应频繁同步写入 Flash，也不能阻塞安全任务。
8. 重复事件必须具备幂等性，不重复创建客户端、任务或连接。

## 9. 初始化顺序

建议按以下顺序执行：

1. 初始化 NVS 和系统基础设施。
2. 创建应用事件循环并注册事件处理函数。
3. 初始化配置及日志模块。
4. 初始化传感器、温控和安全模块。
5. 初始化 LED 状态模块。
6. 初始化并启动 Wi-Fi 管理模块。
7. 初始化 MQTT 管理模块，但不提前连接。
8. 收到 `WIFI_GOT_IP` 后，启动或恢复 MQTT 连接。
9. 根据本地温控及安全条件判断是否发布 `DEVICE_READY`。

如果模块 API 存在特殊依赖，可调整顺序，但必须保证安全模块先进入可控状态，事件处理函数在相关事件产生前完成注册。

## 10. 验收测试

| 编号 | 测试场景 | 预期结果 |
|---|---|---|
| T01 | Wi-Fi 已连接但未获取 IP | MQTT 不连接 |
| T02 | Wi-Fi 获取 IP | MQTT 开始连接 |
| T03 | MQTT Broker 不可用 | 按策略重试，本地温控正常 |
| T04 | Wi-Fi 运行中断线 | 清除网络状态，暂停无效的 MQTT 重连 |
| T05 | Wi-Fi 恢复并获取 IP | MQTT 恢复连接，不重复创建客户端 |
| T06 | MQTT 单独断线 | Wi-Fi 正常时按策略重连 |
| T07 | 重复收到连接事件 | 不重复创建任务或连接 |
| T08 | 收到非法远程命令 | 拒绝命令，不绕过安全逻辑 |
| T09 | 温度传感器故障 | 本地安全逻辑立即处理 |
| T10 | 事件投递失败或记录写满 | 不阻塞安全任务，状态可以恢复 |

## 11. V1.1 实施范围

第一版只实现：

- 一个应用事件循环。
- 统一事件 ID 和发布接口。
- Wi-Fi 获取 IP 后才启动 MQTT。
- Wi-Fi 与 MQTT 各自明确的重连责任。
- 设备就绪和系统错误通知。
- 32 条轻量级事件历史记录。
- 本地温控与网络通信解耦。
- 按验收表测试启动、断线、恢复及安全行为。

暂不引入复杂的通用状态机框架或大量细粒度事件。

## 12. 最终约定

1. Wi-Fi 关联成功不等于网络就绪。
2. `WIFI_GOT_IP` 是 MQTT 连接的必要门槛。
3. Wi-Fi 断线后不得无条件持续重连 MQTT。
4. MQTT 故障不影响本地温控安全。
5. 事件回调保持轻量，耗时操作交给对应模块。
6. 安全动作不依赖事件投递成功。
7. 每类连接只保留一套明确的重连机制。

**本规范作为 ESP32-S3 温控设备事件机制 V1.1 的开发依据。编码时应根据实际使用的 ESP-IDF 6.x 和 ESP-MQTT 版本，核对客户端启动、断开及自动重连接口的具体行为。**
