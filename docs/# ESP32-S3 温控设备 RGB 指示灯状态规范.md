# ESP32-S3 温控设备 RGB 指示灯状态规范

**适用平台：** ESP32-S3、ESP-IDF 6.x、FreeRTOS  
**硬件：** 一颗 RGB 三色 LED  
**版本：** V1.0

## 1. 设计原则

1. 每种运行状态使用明确的颜色和闪烁节奏，避免相似灯效。
2. 全部 LED GPIO 只能由 `led_status` 模块中的 LED 任务控制。
3. Wi-Fi、MQTT、传感器和温控模块只更新状态，不直接控制 LED。
4. 系统故障优先级最高，网络异常次之，正常工作状态最后。
5. LED 仅用于状态提示，不参与温控判断，不得影响继电器安全控制。
6. 启动初始化期间不得因传感器尚未初始化而误报故障。

## 2. 正式状态定义

| 编号 | 状态 | LED 颜色 | 固定显示规则 |
|---|---|---|---|
| L0 | 系统启动、初始化中 | 蓝色 | 亮 200 ms，灭 800 ms，循环 |
| L1 | Wi-Fi 正在连接或重连 | 蓝色 | 亮 200 ms，灭 200 ms，循环 |
| L2 | Wi-Fi 已连接，MQTT 正在连接 | 紫色 | 亮 600 ms，灭 600 ms，循环 |
| L3 | Wi-Fi 或 MQTT 连接断开 | 黄色 | 连闪 2 次，每次亮 150 ms、间隔 150 ms；随后熄灭 1,200 ms，循环 |
| L4 | 系统就绪，温控待机 | 绿色 | 常亮 |
| L5 | 系统就绪，温控正在执行 | 绿色 | 亮 150 ms，灭 1,850 ms，循环 |
| L6 | 系统故障或安全锁定 | 红色 | 连闪 3 次，每次亮 150 ms、间隔 150 ms；随后熄灭 900 ms，循环 |

### 闪烁节奏说明

- “亮 200 ms、灭 800 ms”表示一个完整周期为 1 秒。
- “连闪 2 次”表示两次短亮后进入较长熄灭阶段。
- “连闪 3 次”表示三次短亮后进入较长熄灭阶段。
- 除常亮状态外，所有闪烁周期均由 LED 任务统一计时。
- RGB 颜色按红、绿、蓝三个通道组合实现。紫色为红色与蓝色同时点亮；黄色为红色与绿色同时点亮。

## 3. 各状态的判定条件

### L0：系统启动、初始化中

从上电开始，直到 Wi-Fi 进入连接流程之前，显示蓝色慢闪。

传感器初始化尚未完成时属于正常启动过程，不得仅因此显示红灯。

### L1：Wi-Fi 正在连接或重连

Wi-Fi 驱动已启动，但尚未获得有效 IP 地址时显示蓝色快闪。

Wi-Fi 断线后正在尝试重新连接，也显示此状态；如果需要保留“断线告警”，则在实际断线阶段显示 L3，开始重连后切换为 L1。

### L2：Wi-Fi 已连接，MQTT 正在连接

设备已经获得有效 IP，但 MQTT Broker 尚未连接成功时显示紫色慢闪。

如果 MQTT 正在重连，仍显示此状态，前提是 Wi-Fi 连接和 IP 均正常。

### L3：网络连接断开

出现以下任一情况时显示黄色双闪：

- 已经获得 IP，但 Wi-Fi 随后断开，且尚未进入重连过程。
- Wi-Fi 正常，但已建立的 MQTT 连接断开，且尚未进入重连过程。

当网络管理模块开始重新连接时，按 L1 或 L2 显示连接进度。

### L4：系统就绪、温控待机

必须同时满足：

- Wi-Fi 已连接并获得有效 IP。
- MQTT 已连接。
- SHT40 初始化成功，最近一次温度数据有效。
- 温控模块已完成初始化。
- 系统没有未解除的故障或安全锁定。

满足以上条件且当前没有温控动作时，显示绿色常亮。

### L5：系统就绪、温控正在执行

系统满足 L4 的全部就绪条件，并且温控控制器当前正在执行加热或其他受控动作时，显示绿色短闪。

本状态不表示故障。动作结束后恢复绿色常亮。

### L6：系统故障或安全锁定

发生下列情况之一时显示红色三连闪：

- SHT40 持续读取失败，或传感器数据被判定为无效。
- 温度超出允许范围。
- 温控控制器进入安全锁定。
- 系统检测到其他需要人工检查的关键故障。

故障必须由原有安全逻辑判断。只有确认故障已经恢复并满足解除条件后，才允许退出 L6。

## 4. 状态优先级

当多个状态同时成立时，按以下顺序选择唯一显示状态：

1. **L6：系统故障或安全锁定**
2. **L3：网络连接断开**
3. **L1：Wi-Fi 正在连接或重连**
4. **L2：MQTT 正在连接或重连**
5. **L0：启动初始化中**
6. **L5：温控正在执行**
7. **L4：系统就绪、温控待机**

补充规则：

- 启动期间的正常初始化不算故障。
- 一旦进入故障锁定，红灯优先于网络状态和温控状态。
- Wi-Fi 未获得 IP 时不能显示 MQTT 已连接或系统就绪。
- 温控动作期间发生网络断开，应显示网络状态；发生安全故障则显示红灯。
- Wi-Fi 或 MQTT 断开不应自动等同于温控故障；本地温控是否继续运行由既定安全策略决定。

## 5. RGB 通道定义

| 颜色 | 红色通道 | 绿色通道 | 蓝色通道 |
|---|---:|---:|---:|
| 熄灭 | 关 | 关 | 关 |
| 红色 | 开 | 关 | 关 |
| 绿色 | 关 | 开 | 关 |
| 蓝色 | 关 | 关 | 开 |
| 黄色 | 开 | 开 | 关 |
| 紫色 | 开 | 关 | 开 |

实际 GPIO 电平必须根据 LED 类型配置：

- 共阴 RGB LED 通常为高电平点亮。
- 共阳 RGB LED 通常为低电平点亮。
- 如果使用 WS2812 等可编程 RGB LED，必须采用对应的驱动方式，不能直接套用三个独立 GPIO 的方案。

GPIO 编号、有效电平、限流电阻及引脚冲突情况必须在硬件确认后确定。

## 6. 软件接口约定

建议保留以下简洁接口：

```c
led_status_init(...);

led_status_set_wifi(...);
led_status_set_mqtt(...);
led_status_set_sensor_ok(...);
led_status_set_control_active(...);
led_status_set_fault(...);
led_status_set_ready(...);
```

所有接口只更新状态并通知 LED 任务。LED 任务负责统一判断优先级、生成灯效并操作 GPIO。

不得在 Wi-Fi 回调、MQTT 回调或温控任务中直接改变 LED 引脚。

## 7. 验收测试

固件交付前至少完成以下测试：

1. 上电初始化：蓝色慢闪。
2. Wi-Fi 连接中：蓝色快闪。
3. Wi-Fi 已连接、MQTT 连接中：紫色慢闪。
4. 网络断开：黄色双闪。
5. 系统正常待机：绿色常亮。
6. 温控动作执行：绿色短闪。
7. 传感器故障或安全锁定：红色三连闪。
8. 故障恢复：经安全逻辑确认后恢复到对应运行状态。
9. 网络恢复：按照连接进度切换灯效，最终恢复绿色状态。
10. LED 任务异常：不得影响温控任务、看门狗和安全保护。

**最终要求：同一时刻只显示一个主状态；状态变化由系统实际状态驱动，不允许仅根据时间推测网络或温控是否正常。**
